1. ОБЩИЕ СВЕДЕНИЯ
1.1 Наименование проекта
ImageHost — Закрытый корпоративный веб-сервис для хранения и обмена изображениями

1.2 Цель проекта
Создание безопасной платформы для загрузки, хранения и управления изображениями с возможностью получения прямых ссылок. Система предназначена для использования внутри организации с контролируемым доступом и полным администрированием.

1.3 Задачи проекта
Обеспечить безопасное хранение изображений с защитой от вредоносных файлов

Предоставить пользователям удобный интерфейс для управления медиафайлами

Обеспечить высокую скорость доступа к изображениям через Nginx

Реализовать систему централизованного администрирования пользователей

Предоставить защиту от автоматизированных атак (брутфорс, DDoS)

Обеспечить полное логирование действий пользователей и администраторов

Реализовать систему блокировок (аккаунты + IP-адреса)

1.4 Основные характеристики

2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
2.1 Система аутентификации и авторизации
2.1.1 Создание аккаунта (ТОЛЬКО ДЛЯ АДМИНИСТРАТОРА)
Описание: Администратор создает учетные записи для пользователей. Публичная регистрация отсутствует полностью.

Требования:

Поле	Требование
Имя пользователя	Обязательное, 3-30 символов, латиница/цифры/подчеркивание, уникальное
Email	Обязательное, валидный формат, уникальное
Временный пароль	Генерируется автоматически (12 символов: буквы+цифры+спецсимволы)
Роль	user (по умолчанию) / moderator / admin
Группа/отдел	Опционально, текстовое поле
Бизнес-процесс создания:

Администратор заполняет форму в админ-панели

Система проверяет уникальность username и email

Генерируется временный пароль (12 символов)

Пароль хешируется через bcrypt (соль 10 раундов)

Создается запись в БД с флагом must_change_password = true

Администратору отображается сгенерированный пароль для передачи пользователю любым удобным способом

В аудит-логе фиксируется действие (кто создал, когда, какого пользователя)

Исключения:

При попытке создать существующего пользователя → ошибка 400 "Пользователь уже существует"

При попытке не-админа обратиться к эндпоинту → ошибка 403 "Доступ запрещен"

2.1.2 Вход в систему
Описание: Аутентификация существующего пользователя с защитой от брутфорса.

Поля входа:

Имя пользователя (или Email)

Пароль

Функционал:

"Запомнить меня" — JWT с долгим сроком действия (30 дней)

При первом входе с временным паролем → принудительная смена пароля

Если пользователь заблокирован → сообщение "Ваш аккаунт заблокирован. Причина: ..."

Алгоритм защиты от брутфорса:

Параметр	Значение
Максимум неудачных попыток	3
Окно для попыток	15 минут
Длительность бана	1 час
Сброс счетчика	При успешном входе или по истечении окна
Детальный алгоритм:

text
1. Проверить IP в таблице login_attempts
2. Если IP заблокирован и время бана не истекло → вернуть 429
3. Если IP заблокирован, но время истекло → снять блокировку, сбросить счетчик
4. Проверить, прошло ли 15 минут с первой попытки → если да, сбросить счетчик
5. Проверить логин/пароль
6. Если неудача → увеличить счетчик, проверить на 3 неудачи → заблокировать
7. Если успех → сбросить счетчик, сгенерировать JWT, обновить last_login
Важно: Сообщения об ошибках не раскрывают существование пользователя (всегда "Неверное имя пользователя или пароль").

2.1.3 Восстановление пароля
Описание: Сброс забытого пароля.

Процесс:

Пользователь обращается к администратору

Администратор в админ-панели нажимает "Сбросить пароль"

Система генерирует новый временный пароль (12 символов)

Пароль отображается администратору для передачи пользователю

В аудит-логе фиксируется действие (кто сбросил, кому)

Требования к паролю:

Минимальная длина: 8 символов

Должен содержать хотя бы одну заглавную букву

Должен содержать хотя бы одну цифру

Должен содержать хотя бы один специальный символ

2.1.4 Выход из системы
Описание: Завершение сессии пользователя.

Действия:

Удаление JWT токена на клиенте (localStorage)

Опционально: добавление токена в черный список (Redis)

Перенаправление на страницу входа

2.1.5 Смена пароля
Доступ: Только авторизованные пользователи.

Форма смены пароля:

Текущий пароль (обязательное)

Новый пароль (8+ символов, буквы + цифры + спецсимвол)

Подтверждение нового пароля

Валидация:

Текущий пароль должен совпадать с сохраненным

Новый пароль должен соответствовать требованиям

Новый пароль не должен совпадать с текущим

2.2.3 Блокировка пользователя
Виды блокировки:

Блокировка аккаунта:

Пользователь не может войти в систему

Все активные сессии завершаются (JWT добавляется в черный список)

При попытке входа показывается сообщение с причиной

Блокировка по IP:

Все запросы с IP-адреса пользователя блокируются на уровне Nginx

Добавление IP в глобальный черный список

Можно указать несколько IP-адресов

Форма блокировки:

Поле	Тип	Обязательное	Описание
Блокировать аккаунт	Чекбокс	Да	Блокировка доступа в систему
Блокировать IP	Чекбокс	Нет	Добавление IP в черный список
Причина блокировки	Текст	Да	Причина для пользователя и аудита
Длительность	Radio	Да	Навсегда / На время (часы)
Ограничения:

НЕЛЬЗЯ заблокировать администратора

При попытке блокировки админа → ошибка "Нельзя заблокировать администратора"

Администратор имеет безусловный приоритет

Ограничения:

Обработка изображений (этапы):

Валидация:

Проверка MIME-типа (магические байты через библиотеку file-type)

Проверка размера файла

Проверка расширения

Генерация имени:

Уникальное имя: {uuid}.{ext} (например: 550e8400-...jpg)

Оригинальное имя сохраняется в БД

Оптимизация (для статических изображений):

JPEG: качество 85%, прогрессивный режим

PNG: оптимизация палитры, сжатие

Изменение размера: если ширина > 1920px → ресайз до 1920px

Создание превью (thumbnail):

Размер: 300x300 (fit=cover)

Формат: WebP

Имя: {uuid}-thumb.webp

Сохранение:

Оригинал в папку: /uploads/{uuid}.{ext}

Thumbnail в папку: /uploads/{uuid}-thumb.webp

Информация в БД

Для анимированных GIF и WebP:

Не конвертировать, сохранять как есть

Создавать превью из первого кадра

Сохранять информацию об анимации в БД

7. КРИТЕРИИ ПРИЕМКИ
7.1 Функциональные критерии
✅ Администратор может создать пользователя (указывая username, email)

✅ При создании генерируется временный пароль и отображается администратору

✅ Пользователь может войти с временным паролем

✅ При первом входе пользователь ОБЯЗАН сменить пароль

✅ После 3 неудачных попыток входа IP блокируется на 1 час

✅ Администратор видит IP и User-Agent всех пользователей

✅ IP администратора всегда отображается как 127.0.0.1

✅ Администратор может заблокировать пользователя (с указанием причины)

✅ Администратор может заблокировать IP-адрес

✅ Нельзя заблокировать администратора

✅ Администратор может назначить/снять роль (user/moderator/admin)

✅ Нельзя снять права с другого администратора

✅ Пользователь может загружать JPG, PNG, GIF, WEBP (до 20 MB)

✅ Анимированные GIF и WEBP сохраняются с анимацией

✅ Для GIF и WEBP создается превью из первого кадра

✅ Пользователь получает прямую ссылку на изображение

✅ Пользователь может копировать ссылку в буфер обмена

✅ Пользователь может удалять свои изображения

✅ Все действия администратора логируются

✅ Интерфейс адаптирован для мобильных устройств

7.2 Нефункциональные критерии
✅ Время загрузки страницы < 2.5 секунд

✅ Время обработки изображения < 3 секунд

✅ Система выдерживает 100 параллельных пользователей

✅ Система выдерживает 50 параллельных загрузок

✅ Доступность 99.5%

✅ Все API защищены JWT-токенами

✅ Пароли хешируются через bcrypt

✅ Все файлы проходят MIME-валидацию

✅ EXIF-данные удаляются из загруженных изображений
